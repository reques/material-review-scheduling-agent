## 文件与凭据

- 不提交 `.env`、其他本地密钥文件、`.idea/`、`.venv/` 或生成的临时草稿；`.env.example` 应保留，且不含真实密钥。
- `.gitignore` 只影响正常添加，不能保护已经跟踪、强制添加、另行打包或通过其他途径发送的文件；务必检查最终交付物。
- 真实模型 Trace 和草稿快照只包含合成数据。提交前核对输出是否含真实密钥或隐私数据；不要将密钥内容打印到终端、日志或对话中。
- 查看 `git status --short` 和 `git diff --cached --name-only`，确认暂存的只有预期代码、文档、数据、测试和示例。不要对 `.env` 使用强制添加。

## GitHub 提交

同步时应保留现有 GitHub 仓库的提交历史，并核对仓库归属、可见性和评审访问方式。私有仓库须按题目要求让指定评审账号可读。

提交后用 `git rev-parse HEAD` 获取最终 commit SHA，核对 GitHub 上的 README、测试、数据、文档和示例均与该提交一致。按题目要求提交：**题号 1、GitHub 仓库 URL、最终 commit SHA**。

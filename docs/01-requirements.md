# 01 — 需求说明

## 选题

考试项目题 1：素材审核与发布排期 Agent（100 分）。

## 用户与目标

- 用户：内容团队的运营/审核人员。
- 目标：帮助内容团队找出待处理素材，形成**无冲突、可确认**的发布排期。
- 待处理入口：`--list-pending` 按素材的 `work_status` 筛选，显示缺失字段、草稿、确认与冲突状态；缺少或不认识的状态单独列出。状态由数据维护者维护，不因保存草稿自动变更。

## 输入

- 素材 ID、元数据（标题、类型、时长/格式、版权/授权、负责人、敏感标记、免责声明）；
- 发布时段要求（请求时段）；
- 已有排期；
- 审核规则。

本项目提供以下业务工具（本地函数，见 `src/tools.py`）：素材读取、规则检查、时段查询、草稿保存，另有补查工具用于处理信息缺失分支。

## 交付结果（每项素材）

- 审核状态（`review_status`）；
- 风险原因（`risk_reasons`；规则工具观察中另含规则编号与严重程度）；
- 建议时段（`suggested_slot`）；
- 待确认项（`pending_confirmation`）；
- 草稿保存状态（`draft_saved` / `draft_id` / `duplicate`）。

**仅保存草稿，不接真实发布。** 系统中不存在“发布”工具，任何结果都不得声称已发布（`published` 恒为 `false`）。

## 范围

- 运行方式：CLI（考试允许的 CLI / HTTP API / Notebook 三选一）。
- 模型调用：OpenAI 兼容 HTTP 客户端（标准库 `urllib`）；无真实密钥时提供离线 Mock 入口，并明确标明其边界（见 `docs/02-solution.md` 与 `docs/04-ai-usage.md`）。
- 界面、线上部署、多 Agent、生产级 Runtime 均非必需，不做。
- 数据全部为合成数据（`data/`，虚构 ID M00–M06），不含真实素材与隐私数据。

## 动态决策要求

模型须根据风险或时段冲突，选择补查、替代时段、请求确认或阻塞：

- 风险为阻塞级 → 阻塞，不保存草稿；
- 信息缺失 → 先补查，补查结果改变下一步（补回则继续，仍缺失则阻塞）；
- 时段被占 → 从工具观察到的空闲时段中选替代时段并验证，再保存草稿并标记待确认；
- **未经用户同意，不得擅自改变硬性发布要求**：建议时段不同于请求时段时，必须 `pending_confirmation=true`，并在结果中说明需用户确认。

## 成功标准：六个必须验收点

| # | 验收点 | 预期 |
|---|---|---|
| 1 | 正常排期 | 空闲时段 → 保存草稿，`pending_confirmation=false` |
| 2 | 素材信息缺失 | 补查后仍缺失 → `blocked`，不保存草稿 |
| 3 | 规则风险 | 阻塞级风险 → `blocked`，不保存草稿，列出风险原因 |
| 4 | 时段冲突 | 被占时段 → 建议观察到的空闲时段，`pending_confirmation=true`，仅草稿 |
| 5 | 重复提交 | 同一请求提交两次 → 只产生一份草稿，同一 `draft_id`，第二次 `duplicate=true` |
| 6 | 保存失败 | 保存失败 → 明确返回 `save_failed`，`draft_saved=false`，无 `draft_id` |

参考示例（题目给出）：素材 M01 无风险，用户要求 18:00，该时段已占用、19:00 可用。模型建议 19:00 并标记待确认；**不得称为已发布**。相同请求重复提交只产生一份草稿；保存失败须明确返回失败。

## 确认边界与关键缺陷

- 冲突调整、确认边界、防重复是高分依据。
- **越权发布或虚报发布成功属于关键缺陷**：本项目用 `src/guards.py` 的代码护栏在模型之外强制拦截（见 `docs/02-solution.md`），并有专门单元测试证明声称“已发布”的负载会被降级/拒绝。

## 运行记录要求

- 至少提供两条不同执行路径的运行记录（Trace），体现模型根据不同工具结果调整动作；每条记录包含步骤、工具参数、返回摘要、后续动作与简要决策依据。
- 项目设置执行步数/工具调用次数上限（默认 `max_steps=8`）；达到上限时返回明确的未完成（`incomplete`）状态。
- 不提交模型内部思维过程；Trace 中的 `decision_basis` 仅为模型返回的简短 `thought` 字段截断。

模型：DeepSeek `deepseek-flash`。运行日期：2026-11-05。每次调用都在 `metadata.json` 里记录了 API 主机、请求的模型名、API 返回的模型名、调用次数和有效响应数。没有保存密钥。

## 怎么读这些记录

- `input.json`：本次请求的素材和时段；
- `output.json`：最终结果，`published` 恒为 `false`；
- `trace.json`：每一步的 `action`、`action_input`、`tool_result_summary`、`decision_basis`、`next`；
- `drafts_after.json`：运行结束后草稿存储里的实际记录；
- `metadata.json`：模型和调用信息，不含密钥；
- `acceptance.json`：该组运行的自动检查结果（部分目录有）。

## 历史差异

`20261105T091737242095Z/07-changed-schedule/run2/output.json` 的 `risk_reasons` 是模型原文（`requested_slot_18:00_occupied_by_M00` 等），因为那次运行早于最终的文本控制改动。当前代码会用工具观察生成原因，比如 `已有草稿与当前建议时段不一致`。

历史记录保留原样，不回写。当前行为以 `20261105T093722468190Z/` 和 `src/guards.py` 为准。

另外，`20261105T075237956775Z/` 的冲突场景把状态写成 `draft`，虽然工具已经保存成功。这是第一次真实运行暴露的问题；后来加了基于保存观察的状态归一化，修正记录在 `075334688087Z/`。第一次的记录没有删，方便看修正前后的差异。

## 边界

这些记录是单模型、有限次数的运行，不能代表所有模型和所有输入。Mock 记录在 `examples/01`–`07`，只验证流程，不是真实模型效果的证据。
